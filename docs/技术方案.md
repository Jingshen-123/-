# 技术方案 — 中文语序调整器

## 1. 技术选型

| 层面 | 选型 | 理由 |
|------|------|------|
| 桌面框架 | PyQt6 | 跨平台、组件丰富、QSS 样式灵活、打包方便 |
| AI SDK | openai >= 1.0.0 | DeepSeek API 兼容 OpenAI 接口格式 |
| 配置存储 | JSON 文件 | 轻量，无需数据库，单文件管理 |
| 语言 | Python 3 | 与 PyQt6 和 openai SDK 无缝集成 |

## 2. 架构设计

```
┌─────────────────────────────┐
```

## 3. 模块职责

### config/settings.py
- 管理 API Key 的持久化
- 存储路径：`%APPDATA%/chinese-polisher/config.json`
- 读取时做文件不存在的容错
- API：`get_api_key() -> str`, `save_api_key(key: str) -> None`

### services/text_processor.py
- 封装 DeepSeek API 调用
- 使用 `openai.OpenAI` 客户端，base_url 指向 `https://api.deepseek.com`
- 封装 System Prompt 模板
- API：`polish_text(text: str, api_key: str) -> str`
- 抛出自定义异常以便 UI 层处理

### ui/styles.py
- 提供 `get_dark_theme_stylesheet() -> str` 函数
- 返回完整的 QSS 样式字符串
- 覆盖：主窗口、输入/输出框、按钮、状态栏、滚动条、设置弹窗

### ui/settings_dialog.py
- QDialog 子类
- 包含：Key 输入框（密码模式）、保存/取消按钮、状态文字
- 保存时脱敏显示已保存的 Key
- 与 config/settings.py 交互

### ui/main_window.py
- QMainWindow 子类
- 组合所有 UI 组件
- 协调整体交互流程
- 信号/槽连接

## 4. 数据流

```
用户输入文本
  → 点击「润色」
  → main_window 检查 API Key
  → 无 Key → 弹出 settings_dialog
  → 有 Key → 调用 text_processor.polish_text()
  → 显示加载状态
  → 调用 DeepSeek API
  → 成功 → 输出框显示结果，状态栏显示完成
  → 失败 → 输出框不变，状态栏显示错误信息
```

## 5. 错误处理

| 错误类型 | 处理方式 |
|----------|----------|
| 未配置 API Key | 引导打开设置弹窗 |
| 网络超时 | 状态栏提示"请求超时，请检查网络" |
| API Key 无效 (401) | 提示"API Key 无效，请重新设置" |
| 余额不足 (402) | 提示"API 余额不足" |
| 其他 API 错误 | 显示 API 返回的具体错误信息 |
